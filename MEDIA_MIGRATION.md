# Frame media engine migration

The compatibility baseline is Frame at `84238e6b`. It includes saved presets, stream copy, audio and still-image exports, queue control and the platform-specific restrictions in that revision. HandBrake provides the architectural reference. Its `libhb` calls the codec API for decoding and the format API for muxing. Frame keeps its own conversion rules and interface. [HandBrake decoder](https://github.com/HandBrake/HandBrake/blob/1.11.2/libhb/decavcodec.c) · [HandBrake muxer](https://github.com/HandBrake/HandBrake/blob/1.11.2/libhb/muxavformat.c)

## Implementation plan

1. Inventory the operations generated by `frame-core`, every media process launched by `frame-app`, the test fixture tools and the release packages. Use the media rules and existing output oracles as the baseline.
2. Build one isolated executable, `frame-media`, with the same architecture as Frame. Keep probe timeouts, capture budgets, process ownership, pause/resume, cancellation and output publication in the app. A codec failure can then terminate an individual job.
3. Move metadata, ALAC packet/sample inspection and Opus interval scans to libavformat/libavcodec. Compare stream indexes, time bases, edit lists, hashes and decoded sample counts.
4. Implement shared decoding and filtering for preview, source frame export and encoding. Preserve display orientation, pixel depth, channel layout and clocks across seek, filter delay and EOF. Run the stored filter graphs with libavfilter.
5. Translate each validated export plan into stream mappings, codec contexts, bitstream filters and muxer options. Write completion only after final packets, trailer and output flush. Compare delayed streams, VFR, duplicate mappings, stream tags and protected publication paths.
6. Move capability detection to the linked registries. Encode a real frame to distinguish compiled hardware support from a working device. Bind cached observations to the worker and loaded library files.
7. Build, relocate and exercise each package. Keep the CLI tools as independent fixture generators and reference decoders in tests. Run the release codec checks against the packaged SDK.
8. Run differential tests, fix independent-review reproductions, and record actual platform and device evidence before publishing a release.

## Extending the engine

Add a codec/container combination to `frame-core/media-rules.json`. The registry tests enumerate software export combinations and check them with an independent decoder. Implement new media behavior in the relevant `frame-media/native` module and expose the setting through the existing core planner. Add a small real-media case that asserts the observable effect, including a negative case for invalid or unsupported inputs. For new operations, give the worker an explicit command and declare its cancellation, output-size and completion contracts in the application.

Build the worker before running application tests. Reference tools can be downloaded with `cargo xtask setup-ffmpeg`. The worker accepts an FFmpeg SDK prefix in `FFMPEG_DIR`; pkg-config provides development library discovery on Unix.

```sh
cargo build --locked -p frame-media
cargo test --locked -p frame-media
cargo test --locked -p frame-core --test media_integration -- --ignored --test-threads=1
cargo test --locked -p frame-app --lib
cargo test --locked -p frame-app --lib conversion_runner -- --ignored --test-threads=1
```

Record the commit, SDK, tested package and hardware when interpreting a run. A skipped hardware case, a generated workflow or a registry entry alone provides no evidence of a successful encode on that target.

## Running the device matrix on Windows

From a checkout of this branch, use an x64 developer PowerShell with Python and Rust on PATH. The first command downloads the pinned SDK, builds the worker and stages its DLLs. All outputs stay under `target`.

```powershell
py -3 script/media-worker.py bundle --profile debug --bin-dir target/media-device --lib-dir target/media-device
$env:FRAME_TEST_MEDIA_WORKER = (Resolve-Path target/media-device/frame-media.exe).Path
py -3 script/check-media-hardware.py $env:FRAME_TEST_MEDIA_WORKER --require h264_nvenc | Tee-Object target/nvenc-device.json
cargo xtask setup-ffmpeg
$env:FRAME_TEST_REQUIRED_HW_ENCODERS = "h264_nvenc"
cargo test --locked -p frame-core --test media_integration hardware_video_codecs -- --ignored --nocapture
```

The JSON records GPU model and driver when `nvidia-smi` is available, the tested worker hash, library versions and the decoded picture counts for each working encoder. The Rust test runs the application's plans for each available hardware encoder across the supported containers and bit depths. Its FFmpeg and FFprobe reference executables independently decode and inspect each file. Set `FRAME_TEST_REQUIRED_HW_ENCODERS` to a comma-separated list when a device is known to support additional encoders.

To also build the full Windows application from that checkout, run `./script/bundle-windows.ps1 -Architecture x86_64 -PrepareOnly` in PowerShell. The application and the worker with its DLLs are staged in `target/inno/x86_64`. Start `Frame.exe` there to exercise the same files used by the installer.
